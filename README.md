# Copy Fail (CVE-2026-31431): исследование уязвимости локального повышения привилегий Linux

Учебно-исследовательский проект, посвящённый уязвимости **CVE-2026-31431
«Copy Fail»** — логической ошибке в модуле `algif_aead` подсистемы AF_ALG
ядра Linux, позволяющей непривилегированному пользователю выполнять
управляемую 4-байтовую запись в страничный кэш любого читаемого файла.

Уязвимость публично раскрыта в апреле 2026 года (первоисточники — ниже);
данный проект воспроизводит её механизм в изолированной лаборатории,
разрабатывает собственную реализацию примитива на C, оценивает его
экспериментально и проверяет меры противодействия на трёх дистрибутивах.

> ⚠️ **Границы проекта.** Все эксперименты выполнены в изолированных
> виртуальных машинах (сеть host-only, без выхода в Интернет) с откатом на
> снимки состояний перед каждым опытом. Исследование носит образовательный
> и защитный характер. **Код эксплойта и полезная нагрузка в репозиторий
> не включены** — здесь представлены методика, автоматизация стенда,
> сценарии опытов и результаты.

## Суть уязвимости (в двух словах)

1. Системный вызов `splice()` передаёт в криптографический сокет AF_ALG
   страницы страничного кэша файла **по ссылке**, без копирования.
2. Модуль `algif_aead` с 2017 года выполняет операцию «на месте»: копирует
   в выходной буфер данные, а **тег** прицепляет к выходному списку по
   ссылке (`sg_chain`) — страницы файла оказываются в перезаписываемой
   области.
3. Шаблон `authencesn` (IPsec ESN) пишет служебное поле `seqno_lo`
   (байты 4–7 ассоциированных данных — полностью подконтрольны атакующему)
   по смещению за границей тега — прямо в страницу файла.
4. Проверка HMAC не сходится, вызов возвращает `EBADMSG` — но 4 байта уже
   записаны. Страница не помечается «грязной»: на диске файл не меняется,
   контрольные суммы и время модификации не затрагиваются.

Длина данных в `splice` задаёт **смещение** записи, байты 4–7 AAD —
**значение**. Права на запись в файл не требуются. Перезапись suid-программы
мини-файлом ELF (160 байт) даёт оболочку суперпользователя.

## Главные результаты

| | Ubuntu 24.04.4 | Debian 12.9 | CentOS Stream 9 |
|---|---|---|---|
| Ядро | 6.17.0-14 | 6.1.0-29 | 5.14.0-761 |
| Вердикт детектора | VULNERABLE | VULNERABLE | код встроен в ядро |
| Точность записи (смещения) | 0–16000 | 0–8000 | записи нет |
| Стабильность (прогоны) | 20/20 | 10/10 | 0/10 |
| Полное повышение привилегий | получено (< 1 с) | получено (< 1 с) | нет |
| Причина | фикс отсутствует (февраль 2026) | фикс отсутствует (октябрь 2025) | фикс забэкпорчен (август 2026) |

**Собственные находки, дополняющие публичное описание:**

- на «свежезаписанных» файлах порча достигает диска штатным механизмом
  отложенной записи (writeback); на «чистых» страницах — живёт только
  в страничном кэше и исчезает при сбросе кэша;
- позиция записи зависит от размера буфера чтения (эмпирически выведена
  калибровка `8 + смещение + 4`);
- классический сценарий с `/etc/passwd` блокируется политикой PAM
  (`nullok` отключён) — рабочий вектор именно перезапись suid-программы.

**Проверенные меры противодействия** (все подтверждены отказом эксплойта):

| Мера | Где проверена | Эффект |
|---|---|---|
| Патч ядра (a664bf3d603d, out-of-place) | Ubuntu → ядро 7.0 | все вызовы успешны, записи нет |
| Блокировка модуля `algif_aead` (USN-8226-1) | Ubuntu, Debian | отказ на `bind(AF_ALG)` |
| `initcall_blacklist=algif_aead_init` | CentOS (код встроен в ядро) | отказ на `bind(AF_ALG)` |

записки и рабочих документов, полных журналов экспериментов. Методика
воспроизведения опирается на публичные первоисточники (ссылки ниже).

## Воспроизведение

Общая схема (подробности — `lab/README.md` и `lab/stand/STAND.md`):

1. Три виртуальные машины VirtualBox: Ubuntu 24.04.2+, Debian 12.9,
   CentOS Stream 9 (ядра до апреля 2026 — уязвимый диапазон 4.14–6.19.11).
2. Сеть — только host-only; выход в Интернет лишь на время установки
   инструментов; снимок `vuln-verified` после проверки детектором
   `kwilck/copyfail`.
3. Перед каждым опытом — откат на снимок (`lab/stand/restore_snapshot.sh`).
4. Сценарии опытов предполагают наличие скомпилированного эксплойта
   (не входит в репозиторий) в `~/exploit` целевой машины и собственную
   реализацию по публичному разбору уязвимости.
